# Data Model: Supabase Usage Tracking

**Feature**: 009-supabase-integration-use
**Date**: 2025-10-02

## Entity: UsageRecord

**Table Name**: `adp_usage`

**Description**: Records each Dev Tools button click with associated metadata for usage analytics. Data is retained indefinitely and accessible only via backend/administrative queries.

### Fields

| Field Name | Type | Constraints | Description |
|------------|------|-------------|-------------|
| `id` | UUID | PRIMARY KEY, DEFAULT uuid_generate_v4() | Unique identifier for each usage record |
| `button_clicked_name` | TEXT | NOT NULL | Name/identifier of the Dev Tools button that was clicked |
| `button_clicked_time` | TIMESTAMP WITH TIME ZONE | NOT NULL, DEFAULT NOW() | Timestamp when the button was clicked (user timezone) |
| `input_phrase` | TEXT | NULLABLE | Input phrase provided to the button function (null if not applicable) |
| `response_phrase` | TEXT | NULLABLE | Response phrase generated by the button function (null if not applicable) |
| `result_json` | JSONB | NULLABLE | Complete structured output from the button function |
| `created_at` | TIMESTAMP WITH TIME ZONE | NOT NULL, DEFAULT NOW() | Audit timestamp for when record was created in database |

### Indexes

```sql
-- Primary key index (automatically created)
CREATE INDEX idx_adp_usage_pkey ON adp_usage(id);

-- Time-based queries
CREATE INDEX idx_adp_usage_button_clicked_time ON adp_usage(button_clicked_time DESC);

-- Button-type filtering
CREATE INDEX idx_adp_usage_button_name ON adp_usage(button_clicked_name);

-- Composite index for analytics (button + time)
CREATE INDEX idx_adp_usage_analytics ON adp_usage(button_clicked_name, button_clicked_time DESC);
```

### Constraints

```sql
-- Button name must not be empty
ALTER TABLE adp_usage ADD CONSTRAINT chk_button_name_not_empty
  CHECK (button_clicked_name != '');

-- Button clicked time cannot be in the future (allow 5 min clock skew)
ALTER TABLE adp_usage ADD CONSTRAINT chk_button_time_not_future
  CHECK (button_clicked_time <= NOW() + INTERVAL '5 minutes');
```

### Button Name Values

Expected values for `button_clicked_name` field:

| Button Name | Description |
|-------------|-------------|
| `randomize-all` | "Randomize All Above" button |
| `test-all-models` | "Test All Models" button |

## Data Flow

```
User clicks button
   ↓
Button handler executes
   ↓
Handler completes (success or error)
   ↓
Usage tracking triggered
   ↓
Data extracted from handler context
   ↓
UsageData object created
   ↓
Tracking service called (with 750ms timeout)
   ↓
Supabase INSERT operation
   ↓
Record saved to adp_usage table
   (or silent failure after 750ms)
```

## Validation Rules

- `button_clicked_name`: Must be one of the 6 defined button names, non-empty
- `button_clicked_time`: Must be valid timestamp, not in future (with clock skew tolerance)
- `input_phrase`: Optional TEXT, can be null or empty string
- `response_phrase`: Optional TEXT, can be null or empty string
- `result_json`: Optional JSONB, can be null or any valid JSON structure
- `created_at`: Auto-generated, non-nullable

## Storage Estimates

**Assumptions**:
- 100 button clicks per day
- Average input/response phrase: 200 characters
- Average result JSON: 500 bytes
- Record overhead: ~100 bytes

**Per Record**: ~800 bytes

**Annual Storage**: 100 clicks/day × 365 days × 800 bytes = ~29 MB/year

**5-Year Projection**: ~145 MB

Supabase free tier (500 MB) easily accommodates projected growth.
